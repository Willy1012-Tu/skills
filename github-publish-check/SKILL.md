# 推送 GitHub 前的安全檢查

推上公開倉庫的內容等於公開，一旦推出去就難以收回。照順序做，任何一步發現問題就停下來回報，不要推送。

## 1. 確認範圍

- 要推到哪個倉庫、哪個分支？倉庫是公開還是私人？不確定就問。
- 用 `git status` 與 `git add -n .` 列出這次會提交的檔案，不要直接 `git add -A` 就提交。

## 2. 掃描密鑰

對所有要提交的檔案搜尋：api key、secret、token、password、`sk-`、`ghp_`、`AKIA`、`BEGIN ... PRIVATE KEY`、`.env`、`credentials`。另外確認：

- `.gitignore` 有排除 `.env*`、`*.pem`、`*.key`、本機工具設定資料夾（例如 `.claude/`）。
- 沒有金鑰藏在設定檔、腳本、筆記或截圖裡。

## 3. 掃描個人資訊

- 本機路徑與使用者名稱（例如 `C:\Users\...`、`/home/...`）。
- 真實姓名、Email、電話：包含 LICENSE、README，以及 `git config user.email` 會寫進每個提交的作者資訊。
- 提醒使用者：這些會公開顯示，由使用者決定要不要保留。

## 4. 檢查歷史

密鑰只要曾經進過任何提交，之後再刪除也還留在歷史裡。新倉庫就看 `git log -p` 是否含上述關鍵字。若發現歷史有密鑰：告訴使用者要先到服務端作廢並重新產生金鑰，再清理歷史；只刪除檔案不算解決。

## 5. 給使用者確認

回報：要提交的檔案清單、掃描結果（命中什麼、沒命中什麼）、需要使用者決定的事。使用者明確同意後才推送。使用者的原始要求已明說要推送這批內容時，列清單後可直接推送，但發現任何問題都要先停下來。

## 6. 推送與回報

- 一般推送即可，不使用強制推送，除非使用者明確要求。
- 提交訊息簡短說明做了什麼。
- 推送後回報倉庫連結、分支、提交內容，以及這次沒有檢查到的部分（例如無法確認歷史的情況）。
